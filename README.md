# Mobile Phone Shop Management System

A Java Swing desktop application for managing the day-to-day operations of a mobile phone retail shop. Built with NetBeans IDE, it provides a full-featured point-of-sale (POS) system with inventory management, stock control, staff management, sales reporting, and more.

## Features

- **Point of Sale (POS):** Add items and repair services to a cart, apply discounts, record customer details, and complete sales with invoice generation.
- **Phone & Item Inventory:** Add new mobile phones (with photo, specs such as RAM, battery, display size) and general accessories/items with barcode support.
- **Stock Management (GRN):** Receive stock via Goods Received Notes (GRN), track stock levels, and manage stock returns.
- **Sales Management:** View and search sales records by date range or customer; handle sales returns.
- **Staff Management:** Register staff members, track attendance, and process salary payments.
- **Supplier Management:** Maintain supplier records linked to items.
- **Lookup / Reference Data:** Manage categories, product colours, item sizes, and companies (phone manufacturers).
- **Repairs:** Record repair job details associated with items.
- **Expenses:** Track shop expenses.
- **User Accounts:** Create and manage application user accounts with password protection.

## Architecture

The application follows a simple **two-tier desktop architecture**:

```
┌──────────────────────────────────────────────────────┐
│                   Swing UI Layer                     │
│  (JFrame / JPanel forms generated by NetBeans IDE)   │
│                                                      │
│  Main_Frame  →  JDesktopPane  →  child JPanels       │
└─────────────────────┬────────────────────────────────┘
                      │  JDBC (direct SQL via MyConn)
┌─────────────────────▼────────────────────────────────┐
│               MySQL Database                         │
│         (Mobile_Phone_Shop schema)                   │
└──────────────────────────────────────────────────────┘
```

- All UI classes are **NetBeans-generated form beans** (`.java` + `.form` pairs).
- Database access is centralised in the `MyConn.MyConn` utility class.
- There is **no separate service/DAO layer**; SQL strings are built inline within event handlers.
- The main window (`Main_Frame`) is a `JFrame` with a `JDesktopPane`, and navigation is driven by a left-hand collapsible task-pane menu (using SwingX `JXTaskPane`).

## Database Setup

1. Start your MySQL server.
2. Create the database:
   ```sql
   CREATE DATABASE Mobile_Phone_Shop;
   ```
3. Create a MySQL user or ensure the default credentials are configured (see note below):
   ```sql
   CREATE USER 'root'@'localhost' IDENTIFIED BY '123';
   GRANT ALL PRIVILEGES ON Mobile_Phone_Shop.* TO 'root'@'localhost';
   FLUSH PRIVILEGES;
   ```
4. Import the schema (SQL file not included — you must create the tables manually based on the [Data Models](#data-models) section, or obtain the schema from the original developer).

> ⚠️ **Security Note:** The database username and password (`root` / `123`) are hard-coded in `src/MyConn/MyConn.java`. These credentials should be changed and externalised to a configuration file before any production deployment.

## Build & Run Instructions

### Using NetBeans IDE (Recommended)

1. Open NetBeans IDE (8.x or later).
2. Go to **File → Open Project** and select the `Moble_Phone_Shop` directory.
3. NetBeans will automatically resolve project properties from `nbproject/project.xml`.
4. Right-click the project → **Clean and Build** (or press `Shift+F11`).
5. Right-click the project → **Run** (or press `F6`).

### Using Apache Ant (Command Line)

```bash
# From the project root directory
ant clean build        # Compile the project
ant jar                # Build the distributable JAR
ant run                # Run the application
```

The runnable JAR will be produced at `dist/Mobile_Phone_Shop.jar`.

### Running the JAR Directly

After building, run with:

```bash
java -jar dist/Mobile_Phone_Shop.jar
```

Make sure MySQL is running and the database is set up before launching.

## Notable Issues & Improvement Opportunities

### Security

| Issue | Location | Recommendation |
|-------|----------|----------------|
| Hard-coded database credentials (`root`/`123`) | `MyConn/MyConn.java:17` | Store credentials in an external config file (`.properties`) or environment variable |
| SQL injection vulnerability | All classes using `MyConn.save()` / `MyConn.search()` with string concatenation | Replace with `PreparedStatement` |
| Passwords stored as plain text (inferred from `Users_Details`) | `Others/Users_Details.java` | Hash passwords with BCrypt or PBKDF2 |
| Login form is a stub with no authentication logic | `Main_Frames/Log_In_Frame.java` | Implement real authentication before exposing the app |

### Code Quality

| Issue | Location | Recommendation |
|-------|----------|----------------|
| Static `Connection` object is not thread-safe | `MyConn/MyConn.java:13` | Use a connection pool (e.g., HikariCP) or create per-request connections |
| Deprecated `Date` methods (`getHours()`, `getMinutes()`, `getSeconds()`) | `Others/Pos_System_Frame.java`, `Staff/Staff_Salary_Paying.java` | Replace with `java.time.LocalTime` (Java 8+) |
| All exceptions silently swallowed (`catch (Exception e) {}`) | Throughout all modules | Log or display errors to the user |
| No DAO/service layer; SQL embedded in UI event handlers | All UI classes | Introduce a separate data-access layer to improve maintainability and testability |
| `Dashboard_Panel` is an empty stub | `Main_Frames/Dashboard_Panel.java` | Implement a real dashboard with KPIs (daily sales, stock alerts, etc.) |
| `Log_In_Frame` is an empty stub | `Main_Frames/Log_In_Frame.java` | Complete the login UI and wire up authentication |
| Spelling errors in class/variable names (e.g., `reapir_Price`, `Mamber`) | Various files | Rename for clarity |
